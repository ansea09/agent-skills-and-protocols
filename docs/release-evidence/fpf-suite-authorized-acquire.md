## Change And Acceptance Boundary

The skill reference now maps a Suite source need to Codex's approval-capable
execution tool explicitly. It distinguishes a helper sandbox block from a host
denial, unavailable execution tooling and failure after authorization. One host
request is allowed for the operation; denial stops this route without evasion.
The configured local helper and its guard, updater, sandbox settings and global
environment are unchanged. Only an authorized external child process may drop
an inherited sandbox advisory flag; that flag is not an authorization mechanism.

Acceptance requires actual tool evidence: permission-capable request, operation
outcome, source read and task-owned cleanup, or a precise block and its effect
on the requested work. A plan or verbal promise to ask permission is not a pass.

## Refusal And Failure Acceptance Cases

- Helper says external-download-required: request the host operation if available;
  do not label this a user denial or a failed GitHub request.
- Host denies: do not invoke the download through another route; say that Suite
  was not obtained, identify the blocked work and offer independent work or
  user-supplied sources. No new permission request without a new user decision.
- External execution tool absent: report this host limitation, not a network
  failure; a user may run the trusted helper separately or supply sources.
- Approved download fails: preserve the actual cause and do not claim retrieval
  or attempt an automatic loop to overcome the error.

Real host denial and tool-unavailable paths are not claimed exercised by the
direct success probe. Keep their status distinct from the existing helper-guard
test. Any later scenario/review result must identify whether it was simulated
or an actual host permission outcome. Publication needs separate authorization.
